# Редизайн BARS Assistant

Изменён существующий frontend. Backend, HTTP-маршруты, DTO, авторизация,
ключи идемпотентности и серверный жизненный цикл обращений сохранены.

## Экраны и компоненты

- `App.tsx`: фирменная шапка, зелёная геометрия, навигация по существующим
  ролям, единая светлая тема, обработка viewport и безопасных областей Telegram.
- `Chat.tsx`: приветствие, одна актуальная пара вопрос–ответ, очистка предыдущей
  пары при отправке, защита от отображения результата другого request_id,
  доступный composer и прокручиваемая область ответа. Восстановление запросов,
  повтор с прежним ключом и сценарии поддержки сохранены.
- `Markdown.tsx`: безопасный GFM-рендерер и защищённая галерея сохранены;
  добавлен `MarkdownReveal`. Таблицы и код прокручиваются внутри карточки.
- `Tickets.tsx`: карточки, фильтры открытых/закрытых обращений, обновление через
  существующий polling, раскрываемый контекст с кратким вопросом, переписка,
  сохранение черновика и повтор сообщения. Прокрутка к новым сообщениям
  выполняется, только если читатель находится рядом с концом переписки.
  На десктопе очередь и выбранное обращение расположены рядом; на телефоне
  выбранное обращение заменяет список. Закрытие требует подтверждения.
- `Admin.tsx`: форма допуска, поиск среди загруженных пользователей,
  фактические счётчики загруженных записей, компактные строки доступа,
  подтверждение отзыва, индикация операции и результата. Метрики сохранены.
- `Support.tsx`: единая терминология «обращение», сохранены ожидание,
  подтверждение и переход к существующему обращению без повторного создания.
- `UI.tsx`: общие контурные SVG-иконки, `Orb`, `StatusBadge`, `PageHeading`.

## Дизайн-токены

`frontend/src/tokens.css` содержит заданную в ТЗ палитру navy/green/lime/sky,
семантические поверхности, текст, границы, успех/информацию/предупреждение/
ошибку/неактивность, радиусы, шаги отступов, семейство и размеры шрифта,
минимальную область нажатия, тень и safe-area. Используются системные шрифты
с Inter первым в fallback-стеке; внешней загрузки шрифта нет.

## Анимации

Ожидание: три зелёные точки с волной 900 мс. Ответ полностью разбирается
в Markdown/GFM-дерево. Обычный текст делится на фразы до трёх слов, а жирный
текст, ссылки, элементы списка, заголовки, таблицы и код остаются цельными.
Фразы проявляются с перекрывающимся fade 180 мс, сохраняя своё место в вёрстке
через visibility/opacity. Поэтому строки не перестраиваются при раскрытии.
Шарик отображается непосредственно после текущего фрагмента через псевдоэлемент,
не влияющий на переносы строк. Показ занимает около 4 секунд, предел 4,5 секунды;
темп изменён по замечанию пользователя. Есть «Показать сразу», reduced motion,
финальный импульс и очистка таймеров при смене текста/уходе/размонтировании.
Карточки появляются за 200 мс; нажатие кнопок — scale 0.97 за 110 мс.

  галерея, отсутствие загрузки файлов, роли, текстовый POST, восстановление
  и идемпотентность, подтверждение поддержки, сообщение обращения,
  независимое восстановление ожидающей поддержки, замена предыдущей пары,
  пропуск анимации, reduced motion, фильтры, отмена отзыва доступа и forbidden.
  Дополнительно проверены ошибка изображения, повторная загрузка, Escape
  в увеличенном просмотре и ограниченная по времени анимация без hidden/display:none.
- Backend: `python -m unittest discover -s tests -v` — 9 тестов прошли, включая
  передачу бинарных изображений и безопасных заголовков через HTTP-прокси.
- `npm run build`: TypeScript и production-сборка Vite прошли.
- `git diff --check`: ошибок пробелов нет (Git сообщает о нормализации LF/CRLF).
- Визуальная проверка настоящих компонентов в браузере с временными
  изолированными ответами: стартовый экран; чат с длинным кодом и таблицей
  на 320 px; переписка и допуски на 390 px; двухколоночная очередь на десктопе.
  На 320 px ширина документа составила 320 px, таблица и код около 247 px,
  нижний край composer — 724 px при высоте viewport 740 px.
- Тестовые ответы не добавлены в рабочие экраны. Временный HTML предпросмотра
  удалён. Backend и реальные модели при этих проверках не запускались.

## Ограничения существующего API

- Есть только роли `user` и `admin`; отдельная роль оператора не добавлена.
- У созданных обращений доступны открытое/закрытое состояния. «В работе»,
  назначение оператора и «Взять в работу» не выдумываются на клиенте.
- Список не содержит темы, последнего сообщения и времени последней активности:
  карточка показывает реальный request_id и дату создания. Полный вопрос и
  ответ доступны в контексте выбранного обращения. Глобальные счётчики API
  не предоставляет; фильтры и счётчики относятся к загруженным страницам.
- API допуска меняет только enabled. Редактирование ролей и назначение
  администратора в интерфейс не добавлены.
- Отправка вложений и подтверждения прочтения не поддерживаются и не показаны.
  Защищённые изображения готового ответа продолжают работать.

## Оставшиеся проверки и улучшения

Требуется ручная проверка в Telegram Android/iOS/Desktop, в частности
экранной клавиатуры, SDK safe-area и нативных диалогов подтверждения.
Сквозной запуск с реальными RAG-ответами не выполнялся.
Тёмная тема и сложный морфинг точек относятся к следующему этапу.
Текущая анимация раскрывает готовые фразы, сохраняя форматирование. Самостоятельная загрузка Inter не добавлена.

## Повторяемый визуальный стенд

Запуск из `frontend`: `npm run dev`, затем http://127.0.0.1:5173/preview/.
Страница `frontend/preview/index.html` использует `src/preview.tsx` и настоящие
компоненты `Answer`, `MarkdownReveal`, `GalleryImage`, `Orb`. Есть кнопки повтора
анимации и воспроизведения ошибки картинки. Чтобы проверить повтор после сбоя:
«Проверить ошибку картинки» → дождаться ответа → «Восстановить загрузку» →
«Повторить загрузку изображения» в галерее.

Схема `preview/diagram.svg` — явно обозначенный тестовый файл. Только на странице
стенда перехватывается запрос одного fixture image_id. Нет подмены авторизации,
запросов к backend или подключения стенда в рабочий `main.tsx`. Production Vite
собирает только основной `index.html`, а entry стенда дополнительно ограничен
`import.meta.env.DEV`.

В браузере проверены вложенные списки, GFM-чекбоксы, широкая таблица, Python-код,
ссылки и форматирование; загрузка схемы, ошибка, восстановление через штатную
кнопку повтора и увеличенный просмотр. Реальные изображения из RAG-хранилища
в этом прогоне не проверялись: проверки галереи выполнялись на fixture, а
HTTP-прокси — с тестовым upstream.
