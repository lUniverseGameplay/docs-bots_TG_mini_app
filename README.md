# Telegram Mini App для docs-bots

Отдельный frontend и HTTP backend для существующего RAG API. Вопросы, допуск,
роли, результаты и тикеты принадлежат docs-bots. Здесь нет доступа к его БД,
очередям или моделям. Новый вход принимает **только текст**. Кнопка прикрепления
изображения видна, отключена и ничего не выбирает/отправляет. Ответные изображения
поддерживаются: защищённая галерея под Markdown-ответом.

```text
frontend/                 React + TypeScript + Vite
  src/
    App.tsx               Telegram SDK, тема, роли и навигация
    Chat.tsx              текстовые вопросы, polling и восстановление
    Markdown.tsx          Markdown/GFM, обработка image:// и галерея
    Support.tsx           ожидание, подтверждение и переход к тикету
    Tickets.tsx           свои/все тикеты, история, переписка, закрытие
    Admin.tsx             допуск и бизнес-метрики
    api.ts                initData в Authorization, обработка ошибок
    useResource.ts        polling, отмена fetch и backoff
  Dockerfile, nginx.conf
backend/
  miniapp/app.py          разрешённые HTTP-прокси маршруты
  tests/                  проверки границы HTTP
  requirements.txt, Dockerfile
deploy/Caddyfile.example  HTTPS frontend/backend и публичный RAG API
compose.yaml              два контейнера, общая внешняя Docker-сеть
.env.example              конфигурация без секретов
```

Пользователь: чат, свои тикеты и переписка. Администратор дополнительно получает
все тикеты, операторские ответы/закрытие, управление допуском и метрики в том же
интерфейсе. Роль проверяется RAG API на каждом запросе. Публичный список допуска
username не даёт роль администратора.

## Подготовка docs-bots

Используйте интеграционный код и миграцию `003_mini_app` из соседнего репозитория.
Перед обновлением сделайте backup PostgreSQL. Обновите **все** RAG-процессы до
одной версии до включения веб-приёма. Миграция не удаляет Telegram updates,
вопросы, кнопки, доставки, тикеты или outbox. Прежние callback и незавершённые
работы продолжаются. Не отключайте `relay`, `questions`, `results`,
`maintenance`, `recovery` или ingestion.

Из `docs-bots/app` в обычном окружении приложения:

```powershell
python -m rag.runtime migrate
```

Для контейнерного запуска выполните эту же команду внутри контейнера с новым
кодом и прежним env. Она должна завершиться до запуска обновлённых HTTP/worker
процессов; существующие команды запуска RAG сохраняются.

В корневом `.env` **docs-bots** добавьте:

```dotenv
MINI_APP_ENABLED=true
MINI_APP_URL=https://mini.example.org
MINI_APP_ADMIN_IDS=123456789
MINI_APP_AUTH_MAX_AGE_S=3600
```

ID первого администратора задайте из проверенного Telegram-профиля, а не
username. Проверенный собственный ID возвращает `GET /api/v1/me` после входа из Telegram.
Несколько ID разделяются запятыми. Это единый серверный источник ролей;
изменение применяется после обновления окружения/restart HTTP API. Токен бота,
webhook secret и старые ADMIN_LOGIN/PASSWORD остаются только в docs-bots. Новые
административные ручки не используют Basic credentials.

Проверка подписи initData выполняется в RAG API. Backend Mini App передаёт
`Authorization: tma <raw initData>` без преобразования. Username и роль из тела
вопроса отклоняются. После истечения auth_date нужно переоткрыть приложение;
идентификатор текущего вопроса/неподтверждённый POST восстановятся по Telegram ID.
Не публикуйте initData в логах или URL и не сохраняйте его в браузере.

Первый администратор может открыть «Допуск» даже при пустом списке сотрудников.
Разрешите свой и пользовательские username. Для отправки новых вопросов допуск
нужен и администратору. Отключение допуска не отменяет уже принятый результат.

## Контейнеры на одном сервере

Создайте общую сеть один раз, если её ещё нет:

```text
docker network create rag-shared
```

Подключите существующий HTTP-контейнер docs-bots к сети с alias `rag-api`:

```text
docker network connect --alias rag-api rag-shared EXISTING_RAG_API_CONTAINER
```

Если контейнер уже состоит в сети, задайте alias в его существующем Compose и
пересоздайте штатным способом. Не подключайте backend Mini App к базам/моделям.

В этом репозитории скопируйте `.env.example` в исключённый `.env`, замените
домен. `RAG_API_BASE_URL=http://rag-api:8000` использует внутренний порт API;
при другом порте измените конфигурацию. Далее:

```text
docker compose up -d --build
docker compose ps
```

Frontend слушает `127.0.0.1:8081`, backend — `127.0.0.1:8080` на хосте.
Публичный HTTPS настраивается отдельно, пример — `deploy/Caddyfile.example`.
Реальные домены должны указывать на сервер. Используйте свободные порты либо
измените привязки/пример proxy вместе. Nginx frontend обслуживает статику;
маршруты `/api/*` и `/sources/*` HTTPS proxy направляет в backend. Браузер
обращается к одному origin: CORS для RAG API не нужен.

Существующий HTTPS-домен RAG API и `/telegram/webhook` сохраняются. Новые
`/api/v1/*` можно вызывать через его публичный HTTPS-домен с той же авторизацией;
внутри Docker backend обращается напрямую по HTTP. Backend не передаёт клиенту
секреты, административные заголовки или произвольные upstream URL.

## Telegram

В BotFather выберите **тот же бот**, настройте Main Mini App и Menu Button на
`https://mini.example.org`. Включите новый флаг и перезапустите RAG API.
Команды `/start`, `/help` и обычные личные сообщения возвращают кнопку открытия
приложения. Старые callback-кнопки продолжают прежний путь обработки. При
`MINI_APP_ENABLED=false` webhook работает по прежним правилам.

Проверяйте на телефоне и desktop Telegram. Просто открыть URL в браузере
недостаточно: без подписанного initData сервер отклоняет доступ. Производственного
обхода авторизации для разработки нет.
[Telegram SDK и настройка Mini Apps](https://core.telegram.org/bots/webapps).

## HTTP

Frontend и backend используют одинаковые пути `/api/v1`:

| Метод     | Путь                                | Назначение                                                   |
| --------- | ----------------------------------- | ------------------------------------------------------------ |
| GET       | `/me`                               | проверенный пользователь, роль, допуск, активный вопрос      |
| POST      | `/questions`                        | текст; обязательный `Idempotency-Key`, 202 с request_id      |
| GET       | `/questions/{request_id}`           | собственное состояние и исходный QuestionOutcome             |
| POST      | `/uploads`                          | 501, приём изображений отключён                              |
| GET       | `/images/{image_id}`                | байты изображения из собственного ответа                     |
| POST      | `/questions/{request_id}/support`   | reason: dissatisfied или human_request                       |
| GET       | `/support/{case_id}`                | собственное обращение и устойчивый таймер                    |
| GET       | `/support`                          | свои незавершённые обращения, независимо от текущего вопроса |
| POST      | `/support/{case_id}/confirm`        | подтвердить помощь после 10 минут                            |
| POST      | `/support/{case_id}/decline`        | отказаться после ожидания                                    |
| GET       | `/tickets`                          | собственные open/closed тикеты с пагинацией                  |
| GET, POST | `/tickets/{case_id}/messages`       | TicketView / TicketMessageInput                              |
| GET       | `/admin/tickets`                    | все тикеты, только admin                                     |
| GET, POST | `/admin/tickets/{case_id}/messages` | просмотр и операторские сообщения                            |
| POST      | `/admin/tickets/{case_id}/close`    | закрыть тикет                                                |
| GET       | `/admin/users`                      | список допуска, пагинация по username                        |
| PUT       | `/admin/users/{username}`           | JSON enabled: boolean                                        |
| GET       | `/admin/metrics`                    | aware from_at/to_at, бизнес-метрики и веб-длительности       |

Списка вопросов нет. Вопросы не образуют контекст. GET текущего результата
опрашивается каждые 3 секунды с backoff; поддержка/тикет — каждые 5 секунд.
Идемпотентный ключ POST сохраняется вместе с текстом до подтверждения приёма.
Неоднозначная сетевая ошибка допускает повтор того же запроса. Сообщение тикета
аналогично использует UUID client_message_id; автор назначается сервером.

`GET /sources/{document_id}` проксирует прежнюю публичную HTML-заглушку источника.
Она показывает метаданные; постоянного просмотра полных исходных Markdown-файлов
в существующем RAG API нет. Ответы рендерятся непосредственно из answer_text.
`GET /health/live` и `/health/ready` доступны у backend для эксплуатации.

Закрытый тикет читается, но новые сообщения запрещены. Существующие публичные
ссылки `/tickets/{case_id}` на домене RAG API сохраняют прежнюю доступность всем
обладателям ссылки; новые защищённые Mini App ручки этого не меняют.

## Разработка и проверки

### Локально на Windows: Docker Desktop + ngrok

`deploy/compose.local.yaml` поднимает отдельный проект `docs-mini-local`:
PostgreSQL, RabbitMQ, Redis, Qdrant и S3. Пароли берутся из соседнего
`docs-bots/.env`; PostgreSQL опубликован на `127.0.0.1:55432`, чтобы не мешать
установленному в Windows PostgreSQL. Остальные порты: 5672, 6379, 6333 и 9000,
тоже только на loopback. Данные сохраняются в именованных Docker-томах.

Запускайте `deploy/local_ngrok.py` из Python 3.12 с зависимостями docs-bots и
Mini App backend; `frontend/node_modules` должен быть установлен через `npm ci`.
Требуются работающий Docker Desktop, Node и авторизованный ngrok (`ngrok config
check`). Скрипт находит Docker Desktop и ngrok в PATH либо в локальных путях
этого стенда. Пример из каталога Mini App:

```powershell
$py = "..\docs-bots\app\.venv-miniapp\Scripts\python.exe"
& $py deploy/local_ngrok.py start --admin-id 123456789
& $py deploy/local_ngrok.py status
```

По умолчанию скрипт запускает локальный тест **без моделей**: вход через
Telegram, чат-интерфейс, тикеты, допуск и административные экраны. POST вопроса
возвращает понятный 503 `local_rag_disabled` до обращения к RAG API: вопросы не
зависают в очереди без обработчика. Генерация ответов, индексация и проверка
качества RAG в этом режиме не выполняются. Остальные API работают с реальной БД.

Только при явном `--with-models` скрипт загружает выбранные в `RAG_MODEL_BINDINGS`
модели Ollama и проверяет их через существующий Model Gateway. Для этого режима он использует
портативную Ollama на CPU из `docs-bots/app/.tools/ollama/ollama.exe`, если она
установлена; иначе поднимает официальный контейнер Ollama. Первая загрузка
моделей может занять время. Смена моделей/профилей автоматически не выполняется:
несовпадение digest останавливает проверку. Для уже подготовленной
инфраструктуры/моделей предусмотрен `--skip-infra`.

Затем запускаются миграции, подготовка хранилищ, RAG API на 8000, четыре фоновые
роли Runtime (`questions` добавляется только с `--with-models`), backend на 8080
и frontend Vite на 5173. Это локальный dev-запуск;
ingestion HTTP и ingestion worker запускаются отдельно, если нужны новые
документы. Пустая база не содержит документации для содержательных ответов RAG.

Один HTTPS-туннель ngrok ведёт на Vite. `/api` и `/sources` проксируются в
backend Mini App, `/telegram/webhook`, прежние `/admin` и `/tickets` — в RAG API.
Скрипт записывает HTTPS origin, флаг Mini App и ID администратора в
`docs-bots/.env` (перед этим сохраняет копию в игнорируемом `app/.tools`), а
внутренние контейнерные адреса заменяет только в окружении локальных процессов.
Frontend не получает токен бота или пароли. Доверяется только конкретный hostname
выданного туннеля. Инспекция HTTP-запросов ngrok отключена.

После проверки готовности скрипт явно регистрирует webhook без удаления
ожидающих updates и настраивает Menu Button этого бота на новый URL. Откройте
Mini App кнопкой меню в Telegram. Администратор может войти в «Допуск» и
разрешить свой Telegram username; для отправки вопросов допуск нужен всем.
Main Mini App в профиле бота при необходимости настраивается отдельно в
BotFather на URL из команды `status`. При новом запуске адрес может измениться.

Логи и список собственных процессов находятся в игнорируемом `.local/`.
Остановка проверяет PID и время создания процесса, чтобы не завершить чужой
процесс при повторном использовании PID:

```powershell
& $py deploy/local_ngrok.py stop
docker compose --env-file ../docs-bots/.env -f deploy/compose.local.yaml stop
```

Первая команда останавливает локальные процессы и туннель, вторая — Docker
инфраструктуру. Тома и данные сохраняются. После остановки туннеля webhook и
Menu Button продолжают указывать на его прежний URL до следующего запуска или
явной перенастройки. На публичном dev-адресе ngrok бесплатный тариф может
показать стандартную страницу подтверждения перехода.

Python backend (3.12): установить `backend/requirements.lock`; из backend:

```text
python -m unittest discover -s tests -v
uvicorn miniapp.app:app --host 127.0.0.1 --port 8080 --no-access-log
```

Frontend (Node 24, lockfile включён):

```text
cd frontend
npm ci
npm test
npm run build
npm run dev
```

Для HTTPS dev-прокси укажите его реальный origin в MINI_APP_PUBLIC_ORIGIN.
При локальном запуске задайте RAG_API_BASE_URL (например, http://127.0.0.1:8000)
и MINI_APP_PUBLIC_ORIGIN в окружении процесса: файл .env автоматически читает
Compose, а не прямой запуск Uvicorn.
Vite проксирует API и источники на локальный backend. Секреты во frontend не нужны.

В docs-bots выполните полный unittest, проверки/сборку docs. Для настоящего
PostgreSQL подготовлен opt-in набор `test_mini_app_integration.py`: задайте
`RUN_MINI_APP_INTEGRATION=1` и PGHOST/PGPORT/PGDATABASE/PGUSER/PGPASSWORD тестовой
БД. Используются случайные схемы, рабочие таблицы не очищаются.

При доступной полной инфраструктуре дополнительно проверьте:

1. Вход пользователя/admin и запрет подделки роли/username; отказ чужим UUID.
2. Текстовый вопрос → новый/кешированный ответ; Markdown, источники, изображения
   только под соответствующим ответом, увеличение; отсутствие запросов uploads.
3. Двойной POST/обрыв ответа; один активный вопрос; закрыть Mini App во время
   генерации, открыть после готовности, убедиться в освобождении слота.
4. Сбой/перезапуск questions/relay/recovery; отсутствие повторной генерации и
   Telegram-уведомлений для веб-вопроса.
5. Guardrails, пустой поиск, техническая ошибка; автоматический тикет.
6. «Ответ не помог»/«Нужна помощь» → ожидание 10 минут → reopen → confirm/decline;
   созданный тикет, ответы пользователя/оператора, повтор сообщения и закрытие.
7. Старая Basic-админка, публичная ссылка тикета, источники, прежние callbacks и
   незавершённые Telegram-доставки; ingestion и прочие модули без регрессий.

Не выдавайте UI/HTTP проверки на тестовых ответах за сквозной запуск с реальными
моделями. Отчёт о фактически выполненных проверках приведён в `VERIFICATION.md`.
